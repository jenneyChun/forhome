# QA Agent Brief

## 목적

이 문서는 QA agent가 ForHome 변경사항을 검증할 때 반복 분석을 줄이기 위한 기준 문서다.

QA agent는 전체 코드를 다시 읽기보다 `docs/pm-requirements.md`, `docs/user-flow.md`, 이 문서를 먼저 확인한다.

## 핵심 검증 관점

ForHome의 핵심 품질 기준은 다음 흐름이 깨지지 않는 것이다.

```text
기록 -> 증빙 -> 확인 -> 피드/요약 -> 인정 -> 협업
```

## P0 검증 항목

### 로그인/권한

- 가족 구성원으로 로그인할 수 있는가
- 관리자 계정으로 설정 화면에 접근할 수 있는가
- 성인 권한과 아이 권한 표시가 구분되는가
- 아이 권한 사용자가 성인 전용 승인/육아 설정을 수행하지 못하는가

### 가족 구성원 관리

- 가족 구성원을 추가할 수 있는가
- 이름과 권한을 설정할 수 있는가
- 추가된 성인 구성원이 성인 선택 목록에 나타나는가
- 추가된 아이 구성원이 아이 선택 목록에 나타나는가

### 집안일 기록

- 수행자와 집안일을 선택해 기록할 수 있는가
- 사진 또는 메모 증빙을 남길 수 있는가
- 새 기록은 승인 전 `pending`인가
- 승인 후에만 피드/포인트/XP에 반영되는가

### 승인/반려

- 리뷰 큐에 확인할 기록이 표시되는가
- 승인 시 `approved`가 되는가
- 반려 시 `rejected`가 되는가
- child 카테고리 기록은 성인 승인자가 필요하게 잡히는가

### 항목 변경 승인

- 집안일 항목 추가가 즉시 반영되지 않고 변경 승인 큐에 들어가는가
- 집안일 항목 삭제가 즉시 반영되지 않고 변경 승인 큐에 들어가는가
- 육아 항목 추가/삭제도 변경 승인 큐에 들어가는가
- 승인 후 실제 항목 목록에 반영되는가
- 반려 후 실제 항목 목록에 반영되지 않는가
- 기본 `교육` 항목은 삭제할 수 없는가

### 육아 기록/교육 포인트

- 육아 기록에서 항목, 성인 담당자, 아이를 선택할 수 있는가
- `교육` 항목 기록 시 성인과 아이 모두 포인트를 받는가
- 교육 외 항목은 기본적으로 성인 담당자만 포인트를 받는가
- 육아 기록이 주간 포인트/휴식 추천 계산에 반영되는가

### 백업/리포트

- `scripts/firestore-backup.js`가 문법 오류 없이 실행 가능한가
- 일일 Markdown 보고서에 육아 항목, 포인트 수신자, 설정 변경 요청이 포함되는가
- 아침 브리핑에 pending item changes가 포함되는가

## 주요 리스크

- 기존 데이터에 `role`, `careItems`, `changeRequests`가 없을 수 있다.
- `PARENT_IDS` 고정 로직이 남아 있으면 새 성인 구성원이 승인/육아 흐름에서 빠질 수 있다.
- 항목 변경 요청이 승인 후 중복 적용될 수 있다.
- 교육 포인트가 성인/아이에게 중복 또는 누락될 수 있다.
- 백업 스크립트가 새 필드가 없는 fixture에서 실패할 수 있다.
- PowerShell에서 `npm` 대신 `npm.cmd`를 써야 할 수 있다.

## 기본 검증 명령

```powershell
node --check scripts/firestore-backup.js
npm.cmd test
```

HTML 스크립트 문법 확인이 필요하면 UTF-8로 읽어 추출해야 한다. PowerShell `Get-Content` 기본 인코딩으로 읽으면 한글/이모지가 깨져 가짜 오류가 날 수 있다.

## 회귀 확인 포인트

- 로그인 후 오늘 화면이 열린다.
- 집안일 기록 화면이 열린다.
- 리뷰 화면이 열린다.
- 설정 화면이 열린다.
- 달력/육아 기록 화면이 열린다.
- 기존 백업 dry-run 테스트가 통과한다.
