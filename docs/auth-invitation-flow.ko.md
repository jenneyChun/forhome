# 로그인/가입 및 가족 초대 설계

## 목적

ForHome의 가입은 한 가족 구성원이 먼저 집을 만들고, 그 사람이 다른 구성원을 초대하는 방식으로 구성한다.

이 문서는 다음 흐름을 구현하기 위한 기준 문서다.

1. 대표 가입자가 먼저 계정을 만들고 ForHome 집을 생성한다.
2. 대표 가입자가 초대 URL, QR 코드, 초대 번호 중 하나로 가족을 초대한다.
3. 초대받은 사람은 본인 계정을 만들거나 로그인한 뒤 같은 집에 합류한다.
4. 합류 시 역할을 선택하거나 초대자가 지정한 역할을 확인한다.
5. 역할은 엄마, 아빠, 자식처럼 가족 형태를 고정하지 않고 집안의 책임과 돌봄 관계를 기준으로 나눈다.

## 추천 명칭

기존의 `성인`, `아이`, `엄마`, `아빠`, `자식` 표현은 실제 가족 형태를 좁게 만들 수 있다. 화면에는 다음 명칭을 우선 사용한다.

| 개념 | 추천 표시명 | 내부 역할명 | 설명 |
| --- | --- | --- | --- |
| 최초 가입자 | 대표 히어로 | `owner` | 집을 처음 만들고 초대, 역할, 집 삭제 권한을 가진 사람 |
| 집안일/돌봄 담당자 | 홈 히어로 | `hero` | 집안일을 수행하고 케어 멤버를 돌보는 구성원 |
| 돌봄 받는 구성원 | 케어 멤버 | `care_member` | 홈 히어로의 돌봄을 받거나 보호/지원 대상이 되는 구성원 |

권장 문구:

- `집을 만들 대표 히어로로 시작하기`
- `가족 초대장 보내기`
- `홈 히어로로 참여`
- `케어 멤버로 참여`
- `우리 집 구성원`

피해야 할 기본 문구:

- `부모만 관리 가능`
- `자식 추가`
- `엄마/아빠 선택`

필요할 때만 사용자 입력 이름이나 관계 별칭으로 `엄마`, `아빠`, `할머니`, `삼촌`, `보호자`, `아이` 등을 표시한다.

## 핵심 가입 흐름

### 1. 대표 가입

대표 가입자는 처음 진입 시 다음 중 하나를 선택한다.

- 새 집 만들기
- 초대받은 집에 참여하기
- 기존 계정으로 로그인하기

새 집 만들기를 선택하면 다음 정보를 입력한다.

| 항목 | 필수 여부 | 설명 |
| --- | --- | --- |
| 이메일 또는 로그인 ID | 필수 | PostgreSQL `users.account_id` 또는 `users.email` 식별자 |
| 비밀번호 | 필수 | 서버에서 PBKDF2-SHA256 hash로 저장 |
| 표시 이름 | 필수 | 앱 안에서 보이는 이름 |
| 집 이름 | 필수 | 예: 우리집, 해피홈, 302호 |
| 대표 히어로 프로필 | 필수 | 색상, 표시 글자, 알림 수신 여부 |

가입 완료 후 시스템은 다음을 생성한다.

- 사용자 계정
- 집/가족 단위 데이터
- 대표 히어로 멤버십
- 기본 초대 권한

### 2. 초대장 생성

대표 히어로는 집 설정 또는 구성원 화면에서 초대장을 만든다.

초대장 생성 시 입력값:

| 항목 | 필수 여부 | 설명 |
| --- | --- | --- |
| 초대 대상 표시명 | 선택 | 예: 민준, 할머니. 모르면 비워도 됨 |
| 기본 역할 | 필수 | 홈 히어로 또는 케어 멤버 |
| 만료 시간 | 필수 | 기본 24시간 또는 7일 |
| 사용 횟수 | 필수 | 기본 1회. 가족 공용 초대장은 여러 회 가능 |
| 초대 메모 | 선택 | 카카오톡/문자 공유 시 같이 보낼 안내 |

초대장은 세 가지 형태를 모두 제공할 수 있다.

1. 초대 URL

```text
https://forhome.example.com/invite/<inviteCode>
https://m.forhome.example.com/invite/<inviteCode>
```

2. QR 코드

QR 코드는 초대 URL을 payload로 생성한다. 모바일 카메라로 스캔하면 바로 초대 수락 화면으로 이동한다.

3. 초대 번호

```text
483-921
```

초대 번호는 URL을 열기 어려운 상황에서 직접 입력하는 용도다. 숫자만 쓰면 전달이 쉽지만 추측 위험이 있으므로 짧은 만료 시간과 시도 제한이 필요하다.

### 3. 초대 수락

초대받은 사람은 URL, QR 코드, 초대 번호 중 하나로 초대 수락 화면에 들어온다.

수락 화면에서 보여줄 내용:

- 초대한 집 이름
- 초대한 사람 이름
- 제안된 역할
- 만료 여부
- 이미 사용된 초대인지 여부

초대받은 사람이 계정이 없으면 가입을 먼저 진행한다. 계정이 있으면 로그인 후 초대 수락을 이어간다.

초대 수락 시 입력값:

| 항목 | 필수 여부 | 설명 |
| --- | --- | --- |
| 표시 이름 | 필수 | 초대장에 이름이 있으면 기본값으로 채움 |
| 역할 확인 | 필수 | 홈 히어로 또는 케어 멤버 |
| 관계 별칭 | 선택 | 예: 엄마, 아빠, 할머니, 보호자, 아이, 반려가족 담당 |
| 프로필 표시 | 선택 | 표시 글자, 색상 |

초대받은 사람이 역할을 변경하고 싶을 때:

- 초대장이 `역할 고정`이면 대표 히어로에게 변경 요청을 보낸다.
- 초대장이 `역할 선택 가능`이면 수락 단계에서 직접 고른다.

## 역할과 권한

| 기능 | 대표 히어로 | 홈 히어로 | 케어 멤버 |
| --- | --- | --- | --- |
| 집 이름 변경 | 가능 | 선택 권한 | 불가 |
| 구성원 초대 | 가능 | 선택 권한 | 불가 |
| 구성원 역할 변경 | 가능 | 불가 | 불가 |
| 집안일 수행 | 가능 | 가능 | 선택 가능 |
| 집안일 확인/승인 | 가능 | 가능 | 제한 |
| 케어 멤버 돌봄 기록 | 가능 | 가능 | 보기 중심 |
| 본인 기록 보기 | 가능 | 가능 | 가능 |
| 집 삭제 | 가능 | 불가 | 불가 |

권한은 역할과 별개로 세부 옵션을 둘 수 있다.

```js
{
  role: 'owner' | 'hero' | 'care_member',
  permissions: {
    canInvite: true,
    canManageMembers: true,
    canApproveTasks: true,
    canRecordCare: true
  }
}
```

대표 히어로는 시스템상 `owner`이며, 화면에서는 `대표 히어로`로 표시한다. `owner`는 `hero` 권한을 포함한다.

## 데이터 모델 초안

운영 저장소는 PostgreSQL을 사용한다. 가입/초대는 집 단위와 사용자 단위를 분리한 정규화 테이블로 저장한다.

### 사용자

```sql
users (
  id,
  account_id,
  email,
  password_hash,
  display_name,
  is_admin,
  active,
  created_at,
  last_login_at
)
```

### 집

```sql
households (
  id,
  name,
  owner_user_id,
  created_at,
  updated_at
)
```

### 멤버십

```sql
household_members (
  household_id,
  id,
  user_id,
  name,
  emoji,
  role,
  color,
  restricted,
  created_at
)
```

### 초대장

```sql
invitations (
  household_id,
  id,
  token_hash,
  code_hash,
  role_hint,
  role_locked,
  display_name_hint,
  max_uses,
  used_count,
  expires_at,
  created_by_user_id,
  revoked_at
)
```

보안상 PostgreSQL에는 원본 초대 토큰/번호를 저장하지 않고 hash를 저장한다. URL에는 충분히 긴 token을 붙이고, 사용자는 짧은 초대 번호를 대체 입력 수단으로 쓸 수 있다.

## 화면 흐름

```text
첫 진입
  -> 로그인
  -> 새 집 만들기
       -> 대표 히어로 가입
       -> 집 생성
       -> 초대장 만들기
  -> 초대받은 집 참여
       -> 초대 URL/QR/번호 확인
       -> 로그인 또는 가입
       -> 역할 확인
       -> 집 합류
```

초대 관리 화면:

- 활성 초대장 목록
- 초대 URL 복사
- QR 코드 보기
- 초대 번호 보기
- 초대장 만료/취소
- 사용 횟수와 만료 시간 표시

## 예외 처리

| 상황 | 처리 |
| --- | --- |
| 초대장이 만료됨 | `초대장이 만료되었습니다. 대표 히어로에게 새 초대장을 요청하세요.` 표시 |
| 이미 사용된 1회용 초대장 | `이미 사용된 초대장입니다.` 표시 |
| 잘못된 초대 번호 | 남은 시도 횟수 표시, 반복 실패 시 잠시 제한 |
| 이미 같은 집의 구성원 | 집 홈으로 이동 |
| 다른 집에 이미 속한 사용자 | 집 전환 또는 새 집 참여 확인 |
| 역할 변경 요청 | 대표 히어로에게 승인 요청 생성 |

## 보안 기준

- 초대 URL 토큰은 길고 추측 불가능해야 한다.
- 짧은 초대 번호는 만료 시간을 짧게 두고 입력 시도 제한을 둔다.
- QR 코드는 초대 URL만 담고 개인정보는 담지 않는다.
- 초대장은 취소 가능해야 한다.
- 대표 히어로가 마지막 1명일 때는 집을 삭제하거나 대표를 위임하기 전까지 탈퇴할 수 없다.
- 케어 멤버의 개인정보와 기록은 같은 집의 활성 멤버만 볼 수 있다.

## 구현 우선순위

1. 새 집 만들기와 대표 히어로 가입
2. 초대 URL 기반 참여
3. 홈 히어로/케어 멤버 역할 저장
4. 초대 번호 입력
5. QR 코드 표시
6. 초대장 취소, 만료, 사용 횟수 제한
7. 역할 변경 요청과 승인

## 현재 코드와 연결할 때의 메모

- 현재 `adult` 역할은 `hero`로 이동하는 것이 자연스럽다.
- 현재 `child` 역할은 `care_member`로 이동하되, 나이가 어린 사람만 뜻하지 않도록 화면 문구를 바꾼다.
- 기존 `admin` 계정은 개발용 관리자와 제품 내 `대표 히어로`를 분리해야 한다.
- `PARENT_IDS`처럼 엄마/아빠 고정 id에 기대는 로직은 점진적으로 `role === 'hero'` 기반 helper로 대체한다.
- 설정 화면의 `가족` 섹션은 장기적으로 `구성원` 또는 `우리 집 멤버`로 이름을 바꾼다.
