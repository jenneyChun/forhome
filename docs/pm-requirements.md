# PM 요구명세서

## 문서 목적

이 문서는 ForHome을 집안일을 공유하는 가족 내부 SNS MVP로 발전시키기 위한 PM 관점의 요구명세서다.

기준 문서는 `docs/요구사양서.md`이며, 기능 우선순위는 MVP 성립 여부를 기준으로 `P0`, `P1`, `P2`로 구분한다.

## 우선순위 정의

| 우선순위 | 의미 | 판단 기준 |
|---|---|---|
| P0 | MVP 필수 기능 | 없으면 서비스의 핵심 흐름이 성립하지 않는다. |
| P1 | MVP 직후 강화 기능 | 없어도 첫 버전은 가능하지만, 반복 사용과 협업 경험을 강화한다. |
| P2 | 이후 확장 기능 | 초기 검증 이후에 고도화해도 되는 기능이다. |

## 제품 핵심 흐름

ForHome의 핵심 흐름은 다음 순서로 정리한다.

```text
기록 -> 증빙 -> 확인 -> 피드/요약 -> 인정 -> 협업
```

- 기록: 가족 구성원이 집안일 완료를 남긴다.
- 증빙: 사진 또는 짧은 메모로 실제 수행 내용을 보강한다.
- 확인: 지정된 가족 구성원이 승인하거나 반려한다.
- 피드/요약: 확인된 기록이 가족 피드와 일일/주간 요약에 반영된다.
- 인정: 포인트, XP, 뱃지로 기여를 보여준다.
- 협업: 내일 할 일, 메시지, 육아 담당 등으로 가족 간 역할 조율을 돕는다.

## P0 요구사항

### 1. 로그인

#### 요구사항

- 가족 구성원은 각자의 계정으로 로그인할 수 있어야 한다.
- 기본 계정은 관리자, 엄마, 아빠, 아들 역할을 지원해야 한다.
- 운영 환경에서는 Firebase Auth를 통해 인증해야 한다.
- 로컬 테스트 환경에서는 mock/localStorage 기반 로그인을 허용할 수 있다.

#### PM 의견

MVP에서는 복잡한 가입 절차보다 가족별 고정 계정 기반 로그인이 적합하다. 초기 검증 단계에서는 초대, 비밀번호 재설정, 소셜 로그인보다 안정적인 역할 구분이 더 중요하다.

#### 완료 기준

- 로그인하지 않은 사용자는 공유 데이터에 접근할 수 없다.
- 로그인 후 사용자 역할과 권한이 화면 동작에 반영된다.
- 관리자와 일반 가족 구성원의 권한 차이가 존재한다.

### 2. 집안일 완료 기록

#### 요구사항

- 사용자는 가족 구성원과 집안일 항목을 선택해 완료 기록을 생성할 수 있어야 한다.
- 완료 기록에는 수행자, 집안일, 카테고리, 시간, 포인트, XP가 포함되어야 한다.
- 기록은 최초 생성 시 `pending` 상태가 되어야 한다.
- 승인된 기록만 포인트, XP, 피드, 요약에 반영되어야 한다.

#### PM 의견

집안일 SNS의 시작점은 "누가 무엇을 했는가"를 남기는 것이다. 단, 자기 주장만으로 점수가 쌓이면 신뢰가 약해지므로 완료 기록은 반드시 확인 흐름과 연결되어야 한다.

#### 완료 기준

- 집안일 완료 버튼으로 새 기록이 생성된다.
- 새 기록은 승인 전까지 확인 대기 상태로 남는다.
- 승인 전 기록과 승인 후 기록이 화면에서 구분된다.

### 3. 사진/메모 증빙

#### 요구사항

- 사용자는 집안일 완료 시 사진 또는 메모를 첨부할 수 있어야 한다.
- 사진 없이 메모만으로도 기록할 수 있어야 한다.
- 사진이 있는 경우 미리보기와 함께 저장되어야 한다.
- 증빙 내용은 검토자가 확인할 수 있어야 한다.

#### PM 의견

사진은 신뢰를 높이지만 모든 집안일에 사진이 필요한 것은 아니다. MVP에서는 "사진 또는 짧은 메모"를 허용해 기록 장벽을 낮추는 것이 좋다.

#### 완료 기준

- 사진 첨부가 가능하다.
- 메모 입력이 가능하다.
- 리뷰 큐에서 사진/메모를 확인할 수 있다.

### 4. 검토자 승인/반려

#### 요구사항

- 완료 기록은 지정된 검토자가 승인 또는 반려할 수 있어야 한다.
- 반려 시 반려 메모를 남길 수 있어야 한다.
- 승인 완료 전까지 해당 기록은 공식 완료로 집계되지 않아야 한다.
- 승인 상태는 `pending`, `approved`, `rejected`로 관리해야 한다.

#### PM 의견

ForHome은 단순 체크리스트가 아니라 가족 간 신뢰 기반 피드다. 따라서 "확인했어요" 경험이 서비스의 핵심 인터랙션이다.

#### 완료 기준

- 검토자는 승인과 반려를 선택할 수 있다.
- 반려 기록은 다시 확인이 필요한 상태로 표시된다.
- 승인된 기록만 포인트/XP에 반영된다.

### 5. 엄마/아빠 상호 승인

#### 요구사항

- 엄마가 완료한 집안일은 아빠가 확인해야 한다.
- 아빠가 완료한 집안일은 엄마가 확인해야 한다.
- 본인이 자신의 기록을 승인하는 흐름은 기본적으로 제한한다.

#### PM 의견

부모 간 상호 승인은 MVP에서 핵심 신뢰 구조다. 이 기능이 있어야 집안일 기록이 가족 내부의 인정 체계로 작동한다.

#### 완료 기준

- 엄마 기록은 아빠 리뷰 큐에 표시된다.
- 아빠 기록은 엄마 리뷰 큐에 표시된다.
- 본인 승인으로 공식 완료 처리되지 않는다.

### 6. 아들 child-category 양부모 승인

#### 요구사항

- `child` 카테고리 집안일은 엄마와 아빠 모두의 승인이 필요하다.
- 한 명만 승인한 경우에는 계속 확인 대기 상태로 남아야 한다.
- 두 명 모두 승인하면 최종 승인 상태가 되어야 한다.

#### PM 의견

아이와 관련된 일은 민감도와 책임 공유 수준이 높다. 양부모 승인 규칙은 ForHome이 단순 노동량 계산이 아니라 가족 운영 도구라는 점을 보여준다.

#### 완료 기준

- child-category 기록에는 엄마/아빠 승인 요청이 모두 생성된다.
- 한쪽 승인만으로 최종 완료 처리되지 않는다.
- 둘 다 승인해야 포인트/XP가 반영된다.

### 7. 리뷰 큐

#### 요구사항

- 사용자는 자신이 확인해야 할 기록 목록을 볼 수 있어야 한다.
- 관리자는 전체 확인 대기 목록을 볼 수 있어야 한다.
- 각 항목은 수행자, 집안일, 증빙, 상태, 검토 진행 상황을 표시해야 한다.

#### PM 의견

리뷰 큐는 확인 흐름의 작업함이다. 사용자가 "내가 뭘 확인해야 하는지"를 즉시 알 수 있어야 승인 지연이 줄어든다.

#### 완료 기준

- 로그인 사용자 기준으로 확인할 항목이 필터링된다.
- 관리자는 전체 확인 대기 항목을 볼 수 있다.
- 승인/반려 후 큐 상태가 갱신된다.

### 8. 관리자 기본 설정

#### 요구사항

- 관리자는 가족 구성원, 집안일 항목, 포인트 기준, 계정 정보를 관리할 수 있어야 한다.
- 설정 변경은 저장 후 앱 상태에 반영되어야 한다.
- 일반 사용자는 관리자 수준 설정을 임의로 바꿀 수 없어야 한다.

#### PM 의견

MVP에서는 운영자가 집안일 항목과 가족 구성원을 직접 조정할 수 있어야 한다. 다만 설정 화면은 초기에는 단순하게 유지하고, 가족별 커스터마이징은 이후 단계로 미룬다.

#### 완료 기준

- 가족 구성원 추가/삭제가 가능하다.
- 집안일 항목 추가/삭제가 가능하다.
- 포인트 기준을 설정할 수 있다.

### 9. 백업 기본 동작

#### 요구사항

- Firestore 상태는 GitHub Actions를 통해 날짜별 JSON과 Markdown 보고서로 백업되어야 한다.
- 브라우저 앱에는 GitHub Personal Access Token을 저장하지 않아야 한다.
- 백업 스크립트는 로컬 dry-run으로 검증 가능해야 한다.

#### PM 의견

가족 기록은 누적 데이터다. MVP 단계에서도 데이터 유실 방지를 위한 최소 백업은 필요하다.

#### 완료 기준

- 날짜별 `state.json` 백업이 생성된다.
- 날짜별 일일 Markdown 보고서가 생성된다.
- 테스트에서 백업 dry-run이 통과한다.

## P1 요구사항

### 1. 내일 할 일 공유

#### 요구사항

- 가족 구성원은 특정 날짜의 집안일을 다른 구성원에게 요청할 수 있어야 한다.
- 요청받은 사람은 수락 또는 거절할 수 있어야 한다.
- 수락된 요청은 해당 날짜의 할 일로 표시되어야 한다.

#### PM 의견

이 기능은 기록 중심 MVP를 협업 도구로 확장한다. P0 이후 가족 간 조율 경험을 만드는 핵심 기능이다.

### 2. 일일/하루 마감 요약

#### 요구사항

- 하루 동안 승인된 집안일, 포인트, 메시지, 육아 기록을 요약할 수 있어야 한다.
- 요약은 화면 또는 Markdown 보고서로 확인 가능해야 한다.

#### PM 의견

하루 요약은 가족 피드의 누적 가치를 만든다. 매일 "오늘 우리 집이 어떻게 굴러갔는지"를 보여주는 기능이다.

### 3. 주간 포인트/XP 요약

#### 요구사항

- 주간 기준으로 가족 구성원별 포인트와 XP를 집계해야 한다.
- 포인트가 높은 구성원에게 휴식 추천 상태를 표시할 수 있어야 한다.

#### PM 의견

기존 "피로도" 표현은 부담스럽게 느껴질 수 있으므로 사용자 화면에서는 "포인트"로 표현한다. 내부 계산 이름은 유지하더라도 제품 언어는 긍정적이어야 한다.

### 4. 뱃지 이력

#### 요구사항

- 특정 조건을 달성하면 뱃지를 부여해야 한다.
- 사용자는 자신 또는 가족 구성원의 뱃지 이력을 볼 수 있어야 한다.

#### PM 의견

뱃지는 인정 경험을 강화한다. 다만 MVP 핵심은 승인된 기록이므로 뱃지는 P1로 두는 것이 적절하다.

### 5. 가족 메시지

#### 요구사항

- 가족 구성원은 전체 또는 특정 구성원에게 메시지를 남길 수 있어야 한다.
- 주요 이벤트는 자동 메시지로 남길 수 있어야 한다.

#### PM 의견

메시지는 집안일 기록이 건조한 로그로 끝나지 않게 만든다. 하지만 초기에는 승인/피드 흐름이 먼저 안정되어야 한다.

### 6. 육아 담당/시간 기록

#### 요구사항

- 날짜별 오전/오후 육아 담당자를 기록할 수 있어야 한다.
- 육아 시간은 시작/종료 시간과 메모로 기록할 수 있어야 한다.

#### PM 의견

육아는 집안일보다 책임과 일정 조율의 성격이 강하다. MVP 이후 가족 운영 기능으로 확장하기 좋다.

### 7. 아침 07:00 브리핑

#### 요구사항

- 매일 아침 전날 기록과 오늘 할 일을 요약한 브리핑을 생성해야 한다.
- 로컬 또는 자동화 스크립트를 통해 Kakao 전송을 지원할 수 있다.

#### PM 의견

브리핑은 재방문을 만드는 강한 장치다. 다만 자동화와 외부 전송은 운영 리스크가 있으므로 P1로 둔다.

## P2 후보 요구사항

### 1. AI 사진 분석

#### 요구사항

- 사진을 분석해 집안일 내용, 상태, 추천 문구를 제안할 수 있다.
- 분석 결과는 사용자가 수정하거나 무시할 수 있어야 한다.

#### PM 의견

AI 분석은 매력적이지만 MVP 핵심 신뢰 흐름보다 뒤에 두는 것이 좋다. 먼저 사람이 기록하고 확인하는 흐름이 안정되어야 한다.

### 2. 고급 권한 관리

#### 요구사항

- 가족별 역할, 항목별 승인자, 카테고리별 권한을 세밀하게 설정할 수 있다.

#### PM 의견

초기에는 엄마/아빠/아들/관리자 중심의 고정 규칙으로 충분하다. 고급 권한은 실제 사용 패턴을 확인한 뒤 확장한다.

### 3. 알림 고도화

#### 요구사항

- 승인 요청, 반려, 할 일 요청, 브리핑을 푸시/메신저/이메일로 보낼 수 있다.

#### PM 의견

알림은 사용성을 크게 높이지만 외부 API와 운영 설정 부담이 있다. MVP에서는 앱 내부 표시와 기본 브리핑부터 검증한다.

## MVP 범위 제안

1차 MVP는 다음 기능을 기준으로 한다.

- 가족 로그인
- 집안일 완료 기록
- 사진/메모 증빙
- 승인/반려
- 역할 기반 리뷰 큐
- 승인된 기록만 가족 피드에 표시
- 포인트/XP 기본 집계
- 관리자 기본 설정
- 백업 dry-run 및 GitHub Actions 백업

## 다음 작업 제안

1. `P0` 항목별 현재 구현 여부를 체크리스트로 검증한다.
2. `P0` 화면 흐름을 UX 문서와 맞춰 정리한다.
3. 승인/반려 규칙의 예외 케이스를 테스트로 고정한다.
4. 포인트/XP 표현을 화면 전체에서 제품 언어로 통일한다.
5. `P1` 기능은 MVP 사용 테스트 후 우선순위를 다시 조정한다.
