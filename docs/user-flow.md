# User Flow

## 전체 흐름

```text
앱 접속
  -> 로그인
  -> 오늘 화면
  -> 집안일 기록 / 검토 / 달력 / 뱃지 / 설정
  -> 상태 저장
  -> Firestore 또는 localStorage에 반영
```

## 1. 앱 접속

### 코드에서 확인된 내용

- 사용자는 Firebase Hosting URL 또는 로컬 `http://localhost:8080`으로 앱에 접속한다.
- 로컬 접속은 기본적으로 테스트 저장소를 사용한다.
- 앱 초기화 시 저장소 provider를 선택하고 기존 세션을 확인한다.

## 2. 로그인

### 코드에서 확인된 내용

- 로그인 화면에서 ID와 비밀번호를 입력한다.
- 로컬 테스트 모드에서는 앱 내부 `accounts` 배열과 비밀번호를 비교한다.
- Firebase 모드에서는 입력 ID를 `id@forhome.local` 이메일로 변환해 Firebase Auth에 로그인한다.
- 로그인 후 계정이 관리자이거나 특정 구성원에 연결된다.

### 추정한 내용

- 실제 가족 구성원은 단순 ID를 입력하지만, 운영 인증 계정은 Firebase Auth 이메일 계정으로 관리된다.

## 3. 오늘 화면

### 코드에서 확인된 내용

- 로그인 후 기본 탭은 오늘 화면이다.
- 오늘 완료 기록, 주간 지표, 구성원별 집계, 메시지, 검토 대기 항목 등을 보여준다.
- 오전 7시 이후에는 아침 브리핑 패널이 표시된다.

## 4. 집안일 기록

### 코드에서 확인된 내용

사용자 흐름:

```text
기록 탭 선택
  -> 수행자 선택
  -> 카테고리 선택
  -> 집안일 선택
  -> 사진 또는 메모 입력
  -> 완료 버튼
  -> 승인 요청 생성
  -> 저장
```

- 제한된 구성원은 본인 또는 관리자만 대신 기록할 수 있다.
- 사진을 선택하면 브라우저에서 압축 후 미리보기를 표시한다.
- 완료 기록은 즉시 승인되지 않고 `pending` 상태가 된다.

## 5. 검토 및 승인

### 코드에서 확인된 내용

사용자 흐름:

```text
검토 권한이 있는 사용자 로그인
  -> 확인/뱃지 화면의 검토 대기 항목 확인
  -> 승인 또는 반려
  -> 승인 상태 저장
  -> 모든 필수 승인 완료 시 기록이 approved로 변경
  -> XP/피로도/완료 수 반영
```

- 엄마 작업은 아빠가 검토한다.
- 아빠 작업은 엄마가 검토한다.
- 아이 카테고리 작업은 엄마와 아빠 모두 검토한다.

## 6. 내일 할 일 요청

### 코드에서 확인된 내용

사용자 흐름:

```text
달력 탭 선택
  -> 날짜 선택
  -> 받는 사람 선택
  -> 집안일 선택
  -> 메모 입력
  -> 요청 등록
  -> 받는 사람이 수락 또는 거절
```

- 수락하면 `accepted` 상태가 된다.
- 거절하면 `declined` 상태와 거절 이유가 저장된다.
- 완료 처리하면 `closed` 상태가 된다.

## 7. 육아 담당 및 시간 기록

### 코드에서 확인된 내용

사용자 흐름:

```text
달력 탭 선택
  -> 날짜 선택
  -> 아침/저녁 담당자 선택
  -> 저장
  -> 담당자, 시작 시간, 종료 시간, 메모 입력
  -> 육아 시간 추가
```

- 육아 담당 편집은 관리자 또는 부모 계정이 할 수 있다.
- 육아 시간은 분 단위로 계산된다.

## 8. 뱃지 확인

### 코드에서 확인된 내용

사용자 흐름:

```text
확인/뱃지 탭 선택
  -> 구성원 선택
  -> 획득 뱃지와 잠긴 뱃지 확인
  -> 검토 대기 항목 처리
```

## 9. 설정

### 코드에서 확인된 내용

사용자 흐름:

```text
설정 탭 선택
  -> 피로도 임계값 저장
  -> 구성원 추가/삭제
  -> 집안일 추가/삭제
  -> 계정 추가/삭제
  -> 주간 기록 초기화 또는 전체 초기화
```

### 추정한 내용

- 설정 화면은 관리자 중심으로 사용하도록 설계된 것으로 보인다.

## 10. 백업과 브리핑

### 코드에서 확인된 내용

- GitHub Actions는 Firestore 상태를 읽어 일일 JSON과 Markdown 보고서를 만든다.
- 로컬 Windows 작업 스케줄러는 `send_kakao.ps1`을 매일 07:00에 실행할 수 있다.
- Kakao 브리핑은 백업 스크립트의 `--briefing` 모드를 사용해 생성된다.
