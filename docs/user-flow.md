# User Flow

## 문서 목적

이 문서는 `docs/pm-requirements.md`의 PM 요구사항을 기준으로 ForHome의 사용자 흐름을 정리한다.

ForHome의 핵심 흐름은 다음과 같다.

```text
기록 -> 증빙 -> 확인 -> 피드/요약 -> 인정 -> 협업
```

## 1. 접속

### 사용자 흐름

```text
서비스 접속
  -> 저장소/Firebase 상태 확인
  -> 기존 세션 확인
  -> 로그인 화면 또는 오늘 화면으로 이동
```

### 동작

- 사용자는 Firebase Hosting URL 또는 로컬 테스트 URL로 접속한다.
- 로그인 세션이 있으면 오늘 화면으로 이동한다.
- 로그인 세션이 없으면 로그인 화면을 보여준다.
- 로컬 테스트 환경에서는 localStorage 기반 mock 상태를 사용할 수 있다.

### UX 의견

초기 화면은 사용자가 "오늘 집안일 상태를 보러 왔다"는 목적에 바로 도달해야 한다. 로그인 이후에는 별도 랜딩 페이지보다 오늘 화면으로 바로 이동하는 편이 적합하다.

## 2. 로그인과 권한 선택

### 사용자 흐름

```text
로그인 화면
  -> 계정 입력
  -> 인증
  -> 사용자 역할/권한 확인
  -> 오늘 화면 진입
```

### 동작

- 사용자는 가족 구성원 계정으로 로그인한다.
- 가족 구성원은 엄마, 아빠, 아들 외에도 추가될 수 있다.
- 각 구성원은 이름을 가진다.
- 구성원은 성인 권한 또는 아이 권한을 가진다.
- 성인 권한은 아이 권한보다 더 넓은 승인 권한을 가진다.
- 관리자는 가족 구성원과 권한을 설정할 수 있다.

### UX 의견

로그인 화면에서는 기술적인 계정명보다 가족 안에서 알아볼 수 있는 이름이 중요하다. 로그인 후 상단 또는 프로필 영역에서 현재 사용자가 누구인지, 성인 권한인지 아이 권한인지 명확히 보여줘야 한다.

## 3. 오늘 화면

### 사용자 흐름

```text
로그인 완료
  -> 오늘 화면
  -> 오늘 가족 피드 확인
  -> 확인 대기 기록 확인
  -> 오늘 해야 할 일 확인
  -> 집안일 기록 또는 리뷰로 이동
```

### 동작

- 오늘 화면은 사용자가 가장 먼저 보는 대시보드다.
- 승인된 기록은 가족 피드에 표시된다.
- 승인 대기 기록은 별도 영역에 표시된다.
- 오늘 해야 할 일이 있으면 목록으로 보여준다.
- 포인트와 XP는 승인된 기록 기준으로 집계한다.

### UX 의견

오늘 화면에서는 "이미 가족에게 공유된 일"과 "아직 확인을 기다리는 일"을 분리해야 한다. 그래야 사용자가 기록과 공식 피드를 혼동하지 않는다.

## 4. 집안일 완료 기록

### 사용자 흐름

```text
기록 화면
  -> 수행자 선택
  -> 집안일 항목 선택
  -> 사진 또는 메모 입력
  -> 확인 요청 보내기
  -> 리뷰 큐에 pending 기록 생성
```

### 동작

- 사용자는 수행자와 집안일 항목을 선택한다.
- 집안일 항목은 관리자가 직접 추가, 수정, 삭제할 수 있다.
- 각 집안일 항목은 개별 포인트를 가진다.
- 사용자는 사진 또는 메모를 증빙으로 남긴다.
- 기록은 즉시 공식 완료가 아니라 `pending` 상태로 생성된다.
- 승인 후에만 가족 피드, 포인트, XP에 반영된다.

### UX 의견

기록 버튼은 "완료"보다 "확인 요청"의 의미가 잘 드러나야 한다. 사용자는 집안일을 했다는 사실을 남기고, 가족의 확인을 기다린다는 상태를 자연스럽게 이해해야 한다.

## 5. 사진/메모 증빙

### 사용자 흐름

```text
집안일 선택
  -> 사진 첨부 또는 메모 작성
  -> 미리보기 확인
  -> 확인 요청 보내기
```

### 동작

- 사진은 선택 후 미리보기를 제공한다.
- 메모만으로도 기록할 수 있다.
- 증빙 내용은 리뷰 큐에서 검토자가 확인할 수 있다.

### UX 의견

사진은 신뢰를 높이지만 항상 필수이면 기록 장벽이 높아진다. MVP에서는 사진과 메모 중 하나만 있어도 기록할 수 있게 하는 것이 좋다.

## 6. 리뷰 큐와 승인/반려

### 사용자 흐름

```text
검토 권한이 있는 사용자 로그인
  -> 리뷰 화면
  -> 내가 확인할 기록 확인
  -> 사진/메모 검토
  -> 확인했어요 또는 다시 확인 요청
  -> 기록 상태 갱신
```

### 동작

- 사용자는 자신이 확인해야 할 기록 목록을 본다.
- 관리자는 전체 확인 대기 기록을 볼 수 있다.
- 승인하면 기록은 승인 조건을 다시 계산한다.
- 반려하면 기록은 `rejected` 상태가 되고 반려 메모를 남길 수 있다.
- 모든 필수 검토자가 승인해야 최종 `approved`가 된다.

### UX 의견

리뷰 큐는 "내가 지금 처리해야 하는 일"이 명확해야 한다. 각 항목에는 수행자, 집안일, 증빙, 현재 승인 진행 상태가 함께 보여야 한다.

## 7. 가족 구성원별 승인 규칙

### 사용자 흐름

```text
기록 생성
  -> 수행자와 항목 카테고리 확인
  -> 필요한 검토자 자동 지정
  -> 각 검토자 리뷰 큐에 표시
  -> 필수 승인 완료 시 최종 승인
```

### 동작

- 엄마가 완료한 기록은 아빠가 확인한다.
- 아빠가 완료한 기록은 엄마가 확인한다.
- `child` 카테고리 기록은 엄마와 아빠 모두의 승인이 필요하다.
- 성인 권한 사용자는 아이 권한 사용자보다 더 많은 승인 권한을 가질 수 있다.
- 아이 권한 사용자는 제한된 범위 안에서 기록하거나 확인할 수 있다.
- 본인이 자신의 기록을 승인하는 흐름은 기본적으로 제한한다.

### UX 의견

승인 규칙은 사용자가 직접 계산하지 않아도 되어야 한다. 기록을 생성하면 시스템이 자동으로 "누가 확인해야 하는지"를 보여주는 방식이 적합하다.

## 8. 가족 구성원 관리

### 사용자 흐름

```text
설정 화면
  -> 가족 구성원 관리
  -> 구성원 추가
  -> 이름 입력
  -> 성인/아이 권한 선택
  -> 저장
```

### 동작

- 관리자는 가족 구성원을 추가, 수정, 삭제할 수 있다.
- 구성원 이름을 설정할 수 있다.
- 구성원 권한은 성인 권한 또는 아이 권한으로 설정한다.
- 권한에 따라 승인 가능 범위와 설정 접근 범위가 달라진다.

### UX 의견

가족 구성원 관리는 계정 관리라기보다 "우리 집 구성원 설정"처럼 느껴져야 한다. 이름, 표시 아이콘, 권한을 한 화면에서 간단히 설정하는 흐름이 좋다.

## 9. 집안일/육아 항목 관리

### 사용자 흐름

```text
설정 화면
  -> 집안일 또는 육아 항목 관리
  -> 항목 추가/수정/삭제
  -> 포인트 설정
  -> 변경 요청 생성
  -> 가족 구성원 승인
  -> 최종 반영
```

### 동작

- 사용자는 집안일 항목을 직접 추가할 수 있다.
- 사용자는 육아 항목을 직접 추가할 수 있다.
- 육아 항목에는 기본적으로 `교육` 항목이 포함된다.
- 각 집안일 항목은 개별 포인트를 설정할 수 있다.
- 각 육아 항목도 개별 포인트를 설정할 수 있다.
- 집안일 항목 또는 육아 항목 변경은 가족 구성원의 승인 후 반영된다.

### UX 의견

항목 변경은 가족의 점수 체계에 영향을 준다. 따라서 단순 저장 버튼보다 "변경 요청"과 "가족 승인 후 반영" 흐름이 더 적합하다. 변경 전후 내용이 비교되어야 가족이 승인하기 쉽다.

## 10. 항목 변경 승인

### 사용자 흐름

```text
항목 변경 요청 생성
  -> 승인 가능한 가족 구성원에게 표시
  -> 변경 전/후 내용 확인
  -> 승인 또는 반려
  -> 승인 완료 시 항목 설정 반영
```

### 동작

- 집안일 항목 추가, 수정, 삭제는 변경 요청으로 생성된다.
- 육아 항목 추가, 수정, 삭제도 변경 요청으로 생성된다.
- 변경 요청에는 변경 전 값, 변경 후 값, 요청자, 요청 시간이 포함되어야 한다.
- 가족 구성원이 승인해야 최종 설정에 반영된다.
- 반려 시 변경은 적용되지 않는다.

### UX 의견

기록 승인 큐와 설정 변경 승인 큐는 성격이 다르므로 화면에서 구분하는 것이 좋다. "집안일 확인"과 "설정 변경 승인"을 같은 리뷰 화면 안의 탭으로 나누는 방식이 적합하다.

## 11. 육아 항목과 교육 포인트

### 사용자 흐름

```text
육아 기록 화면
  -> 육아 항목 선택
  -> 참여한 성인 선택
  -> 참여한 아이 선택
  -> 시간 또는 메모 입력
  -> 기록 저장
  -> 교육 항목이면 성인과 아이 모두 포인트 지급
```

### 동작

- 육아 항목은 집안일 항목과 별도로 관리된다.
- `교육` 항목은 기본 육아 항목으로 제공된다.
- 교육 항목을 수행하면 참여한 성인과 아이가 모두 포인트를 받는다.
- 교육 외 육아 항목의 포인트 지급 대상은 항목 설정에 따라 결정할 수 있다.

### UX 의견

교육은 어른이 해주는 일인 동시에 아이가 참여한 활동이다. 따라서 기록 화면에서 "누가 돌봤는가"와 "어떤 아이가 함께했는가"를 함께 선택할 수 있어야 한다.

## 12. 내일 할 일 공유

### 사용자 흐름

```text
일정/계획 화면
  -> 날짜 선택
  -> 받을 사람 선택
  -> 집안일 선택
  -> 메모 입력
  -> 요청 등록
  -> 상대방 수락 또는 거절
```

### 동작

- 가족 구성원은 특정 날짜의 집안일을 다른 구성원에게 요청할 수 있다.
- 요청받은 사람은 수락 또는 거절할 수 있다.
- 수락된 요청은 해당 날짜의 할 일로 표시된다.

### UX 의견

내일 할 일 공유는 지시가 아니라 협업 요청처럼 느껴져야 한다. 거절 사유를 남길 수 있으면 가족 간 조율에 도움이 된다.

## 13. 포인트, XP, 뱃지

### 사용자 흐름

```text
승인된 기록 발생
  -> 포인트/XP 집계
  -> 조건 충족 시 뱃지 지급
  -> 오늘 화면과 요약 화면에 반영
```

### 동작

- 승인된 기록만 포인트와 XP에 반영된다.
- 항목별 설정 포인트가 집계에 사용된다.
- 포인트가 높은 구성원에게 휴식 추천을 표시할 수 있다.
- 특정 조건을 달성하면 뱃지를 부여한다.

### UX 의견

포인트는 경쟁보다 인정과 균형의 언어로 보여주는 것이 좋다. "누가 더 많이 했나"보다 "수고 포인트가 쌓였다", "휴식 추천" 같은 표현이 ForHome의 톤에 맞다.

## 14. 가족 메시지

### 사용자 흐름

```text
메시지 화면
  -> 전체 또는 대상 구성원 선택
  -> 메시지 작성
  -> 전송
  -> 가족 피드 또는 메시지 목록에 표시
```

### 동작

- 가족 구성원은 전체 또는 특정 구성원에게 메시지를 남길 수 있다.
- 주요 이벤트는 자동 메시지로 남길 수 있다.

### UX 의견

메시지는 집안일 기록을 관계의 맥락으로 이어준다. 승인, 반려, 요청, 뱃지 획득 같은 이벤트는 짧은 자동 메시지로 남기면 좋다.

## 15. 일일 요약과 아침 브리핑

### 사용자 흐름

```text
하루 기록 누적
  -> 일일 요약 생성
  -> 다음 날 아침 브리핑 생성
  -> 화면 또는 Kakao로 확인
```

### 동작

- 하루 동안 승인된 집안일, 포인트, 메시지, 육아 기록을 요약한다.
- 아침 07:00 브리핑은 전날 기록과 오늘 할 일을 포함한다.
- 백업 스크립트는 일일 Markdown 보고서와 JSON 백업을 생성한다.

### UX 의견

요약과 브리핑은 가족이 앱을 다시 열 이유를 만든다. 다만 MVP에서는 자동 전송보다 화면에서 정확히 생성되는 것을 먼저 검증하는 것이 좋다.

## 16. 백업

### 사용자 흐름

```text
Firestore 상태 저장
  -> GitHub Actions 실행
  -> 날짜별 JSON 백업 생성
  -> 날짜별 Markdown 보고서 생성
```

### 동작

- Firestore 상태는 날짜별 JSON으로 백업된다.
- 일일 보고서는 Markdown으로 생성된다.
- 브라우저 앱에는 GitHub Personal Access Token을 저장하지 않는다.

### UX 의견

백업은 사용자가 자주 보는 화면 기능은 아니지만, 가족 기록이 누적되는 서비스에서는 신뢰의 기반이다. 관리자 화면에는 마지막 백업 시간 정도를 보여주는 것이 좋다.

## 우선 구현 흐름

MVP에서는 다음 흐름을 우선 구현한다.

```text
로그인
  -> 가족 구성원/권한 설정
```
